# Contributing

Help improve public-record research without turning this repository into a public accusation board.

## Welcome contributions

- Public-source contracts and carefully scoped connector fixes.
- Exact identifier, date, amount-unit and coverage handling.
- Contradictory-evidence and benign-explanation examples.
- Synthetic end-to-end reproductions, documentation and accessibility.

## Do not submit

No real case files, evidence, personal identifiers, credentials, patient/child records, private logs or allegations about named subjects. Use clearly labelled invented data. This project does not accept fraud tips or provide reward eligibility decisions.

## Development

Read AGENTS.md and .env.example. Use uv with the locked project environment. Specify acceptance before implementation; prefer subprocess E2E contracts and retain repeatable JSON receipts privately. Do not write after-the-fact unit tests.

Run all deterministic commands in README. Update `release-files.json` only for intentionally distributable files. Build and scan the exact release after source changes. Do not add network-dependent scans to ordinary CI or any scheduled research.

Use precise claims: source discovered, bytes acquired, schema checked, analysis reproduced. None means misconduct established. Document source drift and preserve negative results rather than weakening checks to make a connector green.

## Review

Keep changes scoped. Explain source coverage, behavior, failure modes, user impact and verification. Maintainers may ask for a smaller synthetic reproduction to avoid disclosure. Public issues and pull requests are visible to everyone; do not use them for sensitive reports.
